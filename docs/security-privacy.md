# 安全与隐私

## 已实现控制

- 微信 `code2session` 登录、JWT、全局角色守卫和商户数据作用域。
- DTO 白名单校验，拒绝未声明字段；金额和数量使用整数边界。
- 串行化事务、条件更新、唯一约束和幂等键防止重复支付、超卖、抢场和重复核销。
- Helmet、CORS、请求 ID、统一异常结构；生产环境禁用开发登录。
- 人工调账、退款审批、参数、比分纠错、券核销、库存和导出均记录操作者与原因。
- 所有 HTTP 写请求额外记录请求 ID、路径、结果、IP 和设备标识；该记录不保存请求体、Cookie、Authorization 或 token，领域事务审计仍是金额/状态前后值的权威证据。
- 用户可提交、查询和撤回数据注销申请；超级管理员在账号停用、职责移交、余额/订单/退款/课包/券/奖励/班次全部结清后，以双人复核完成匿名化。申请、阻断项、驳回或完成决定均有幂等键和审计。
- 用户账户软删除字段、监护人授权字段、通知同意版本和时间均可追溯。

## 数据最小化

系统只保存业务需要的 OpenID、展示名、手机号（可选）、会员标签、订单、签到和账户流水。青少年学员使用出生月份而非完整生日；监护人授权必须在青少年课包购买前完成。

注销完成后，系统清除 OpenID、UnionID、手机号、头像、活动通知和下载地址，匿名化本人及其监护学员、赛事名单和奖品签收姓名，并解除推荐关系。依法或为财务核对所必需的订单、支付、退款、五账户流水、培训收入、库存和审计凭证不物理删除，而是仅以内部分配的匿名 ID 留存并继续受最小权限控制。

日志、导出和错误响应不得输出微信 session key、JWT、支付私钥、完整手机号或未脱敏个人信息。Excel 导出仅对财务/管理员开放并记录审计。

## 生产加固清单

- 在网关增加登录、领券、核销、支付和导出的用户/IP 限流。
- 密钥放入 KMS 或容器 Secret，定期轮换 JWT、微信和数据库凭据。
- API 和数据库分网段，数据库不暴露公网；应用账户使用最小权限。
- 为审计日志设置只追加存储和保留期；高风险事件接入告警。
- 为数据库备份设置加密、访问审批、固定保留期和到期销毁；恢复旧备份后必须重新执行注销增量，避免已匿名账号因灾备恢复重新出现。
- 发布与系统实际注销、留存和导出行为一致的隐私政策；补充青少年监护人撤回授权的独立业务流程。
- 接入真实支付前完成微信平台验签、回调重放保护和日终账单核对。
