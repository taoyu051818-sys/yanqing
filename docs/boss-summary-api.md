# 老板摘要与关键事件接口

入口：PC 管理后台 → 老板摘要。页面仅向管理员、超级管理员、财务开放。所有接口沿用现有身份认证和岗位权限；PC 写请求还需要同源会话和 CSRF 校验。

## 接口

| 方法与路径（前缀 `/api/v1`） | 行为 |
| --- | --- |
| `GET /boss/summary?date=YYYY-MM-DD` | 统一经营指标、时段使用、开放活动、关键事件、扫描状态与统计口径 |
| `GET /boss/briefing?date=YYYY-MM-DD` | 最近一次持久化简报及生成时间，没有缓存时为空 |
| `POST /boss/briefing`，JSON `{ "date": "YYYY-MM-DD" }` | 根据最新指标生成或复用简报；省略日期表示今天 |
| `GET /governance/risk-events` | 既有风险事件完整查询入口 |
| `POST /governance/risk-events/:id/review` | 开始复核，管理员及财务可执行 |
| `POST /governance/risk-events/:id/resolve`、`dismiss` | 管理员处理或排除提醒 |

事件变更请求提交 `reason` 和唯一 `idempotencyKey`，保留操作者、说明和审计记录。未来语音老板层应使用这些受权限保护的接口，不直接访问数据库或给模型业务写权限。

## 数据口径

- 北京时间，今天及过去90天；金额一律以整数分传输。
- 新增订场、代订按订单创建时间统计；代订使用实际订单快照 `operatorAssisted`。
- 全业务已支付按支付成功时间统计，包含充值预收和余额支付；微信实收独立列示。不能将全业务已支付直接当作经营收入。
- 场地收入按履约完成确认；完成前退款在确认时扣除，完成后退款在退款成功日反冲，同一退款只扣一次。
- 当日待支付指当日创建且查询时仍待支付；积压包含更早的待支付订单。历史日期同样使用订单当前状态，不是历史时点快照。
- 取消按取消时间，退款按成功时间；同一订单多次部分退款按一笔退款订单计数，退款金额累计。
- 使用率为确认、签到及完成预约占用分钟 / 可售分钟。排除封场、待支付临时占位；合并重叠记录避免重复计算。使用当前启用场地及营业时段配置，且不计算场地创建前的容量，历史配置没有完整快照。
- 活动始终为查询时当前及未来开放球局/积分赛，不随历史经营日期回放。积分赛双打按每队2人；确认、待支付、候补分别统计。剩余名额扣除有效待支付占位。报名费是累计实付减退款。
- 今日事件包含今日创建和仍未处理的历史事件；历史日期仅列当天创建事件，状态为查询时状态。摘要按严重程度最多返回100条，提供真实 `eventCount` 和 `eventsTruncated`，完整查询使用风险治理接口。

## 自动事件规则

启动后及每5分钟扫描一次。记录规则、严重程度、对象、触发依据、首次发现、最近发现和处理状态。数据库唯一去重键防止重复扫描重复建事件；人工已处理状态不会被扫描重新打开。跨日业务提醒可生成新记录。

| 规则 | 默认条件 |
| --- | --- |
| 大额订单 | 24小时内已付款且≥1000元 |
| 大额充值 | 24小时内充值已付款且≥2000元 |
| 支付异常 | 支付失败，或支付请求等待结果≥10分钟 |
| 待支付积压 | 待支付订单创建≥30分钟 |
| 多笔退款 | 24小时成功退款≥3笔 |
| 即将满员 | 有效报名和待支付占位合计≥90% |
| 报名不足 | 截止前24小时，确认人数低于容量30% |
| 长期空场 | 近7个完整自然日同一时段使用率低于20%，至少3天有可售容量 |
| 场地冲突 | 今日及未来30天查询范围中同场地有效预约重叠，忽略过期临时占位 |

规则阈值通过 `.env.example` 中 `BOSS_*` 配置。此版是周期扫描记录，并非所有状态变化的实时事件流；短暂状态可能在扫描前已结束。提醒是核对线索，不表示系统已证实业务故障。

## LLM

服务端使用 `BOSS_LLM_BASE_URL`、`BOSS_LLM_MODEL`、`BOSS_LLM_API_KEY`。当前按用户指定服务接入 `gpt-5.6-sol`，密钥不进入仓库和前端。

仅发送汇总指标、前三个空闲时段、最多30个公开活动标签与人数、最多30条事件规则摘要及口径；不发送会员联系人、订单编号、微信身份、支付原文或事件原始证据。AI 只生成文字，不能支付、退款、改订单或处理事件。

同一天相同事实15分钟内复用 AI 简报；数据库生成锁90秒、调用间隔至少60秒。调用最多等待55秒，失败时保存确定性数据摘要。缓存显示生成时间，数据刷新后可以重新生成。规则扫描不会自动调用收费模型。

## 复验

1. `pnpm --dir apps/api exec vitest run src/boss`。
2. 后端构建、Prisma 生成后，在一次性本地 PostgreSQL 数据库 `boss_acceptance` 应用迁移并执行 seed。
3. `DATABASE_URL=postgresql://<本地用户>@127.0.0.1:<端口>/boss_acceptance node apps/api/scripts/boss-db-acceptance.mjs`。
4. 该脚本只允许本地指定测试库，会创建合成订单、支付、退款、事件和简报；验证计数、收入、退款去重、事件幂等、人工处理状态保留。不得用于生产数据。
5. PC 用隔离库测试管理员登录，查询日期、生成简报、查看依据、填写说明、标记处理，再勾选显示已处理确认保留。
6. 生产只做健康、权限、真实汇总及模型连通验证，不创建测试订单或发起真实支付。
