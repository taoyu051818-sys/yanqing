# 经营台导航与详情改版

本轮为本地代码修改，尚未部署 API、上传或发布小程序。

## 变化

- 首页改为四列宫格，管理员15个入口集中显示；待办为简短入口，不再展开人员、工作项和大统计卡。搜索覆盖业务与设置入口，按角色过滤。
- 组织人员支持查询、每页20人的翻页；点击在新的页面栈中打开人员权限，详情不再排在人员列表末尾。角色编辑与启停操作固定底部，保留超级管理员限制、原因及确认。
- 客户详情在新的页面栈中打开；概览、订单、账户、参与记录分区。教练只显示其培训范围，前台保留脱敏和账户汇总限制。
- 返回客户列表保留查询和已加载记录，不自动重载清空列表。主理人申请默认收起；相关待办深链仍自动展开并定位。
- 详情复用原领域页面的独立路由参数 `memberId` / `userId`，每次导航生成独立页面实例；客户详情展示独立为组件，避免复制账户调整逻辑。
- 新增组织用户查询的精确 `userId` 条件，仍由服务端管理员权限控制，避免详情依赖前100条人员缓存。模拟接口同步支持该条件和分页。
- MetricCard与经营待办导航工具现仅由经营端使用，移入经营分包，生产包未遗留未使用的主包文件。

## 验证

- 小程序74个文件、449项测试通过；新增详情直达、避免加载整份列表、返回保留条件和身份变化重新加载用例。
- API治理专项11项通过，含精确用户筛选及隐私字段控制；API构建和lint通过。
- 小程序类型检查、微信正式接口构建及包体检查通过；未包含mock文件。
- 本地隔离H5自动验收通过：375×812、320×568首屏显示全部15个入口；812×375横屏无横向溢出；角色保存、详情分类、底栏位置、返回搜索保留、前台与教练权限展示正常。外部网络请求被测试脚本阻止，没有操作生产数据。
- 实际截图、日志见evidence目录。脚本 `scripts/h5-workspace-acceptance.cjs` 使用本地mock H5服务（默认5197端口）和Playwright/Chrome。
- 尚未进行微信真机验收、系统放大字体或深色模式验收。横屏和放大字体允许自然纵向滚动，不压缩操作按钮强行塞入一屏。

## 发布顺序与真机验收

先部署API（组织用户精确筛选），再上传小程序新版本；旧小程序仍可使用新版API。

1. 管理员/前台分别进入经营台，确认宫格入口按权限显示；游客不自动弹登录。
2. 在组织权限搜索人员，翻页后打开详情；保存角色或状态后返回，核对人员状态和分页。
3. 在客户页搜索会员，进入详情分类；返回后核对搜索词、记录与滚动位置。
4. 检查固定底栏在安全区、键盘出现和小屏下不遮挡输入；确认账户调整和角色确认弹窗正常。
5. 教练与前台分别核对详情脱敏；再从待办进入指定会员和主理人申请，确认深链正常。
