# 管理员直接执行：八类工作流简化

日期：2026-09-20。范围：经营台小程序及对应后台业务规则。已完成本地修改与验证，尚未部署或上传微信版本。

后续加固已完成，最终事务边界、后台退款恢复、数据库迁移及验收结果请以 [加固记录](../2026-09-20-admin-execution-hardening/README.md) 为准。以下为最初简化阶段的历史记录。

## 改动

| 工作流 | 管理员、超级管理员的新行为 |
| --- | --- |
| 取消整场球局／赛事 | 确认取消后自动处理该活动的应退申请，包括取消前已有的未执行退款；不必逐条再审核。 |
| 会员账户调整 | 一次确认后直接入账，申请与入账记录均保留。财务角色仍提交申请，不能自审。 |
| 培训消课 | 到场且符合课次时间条件后可直接确认，无需先让教练提交，也允许确认自己的建议。 |
| 撤销错误消课 | 管理员提交后直接冲正，恢复课时与相应账务，原流水保留。教练仍提交申请。 |
| 盘点过账 | 全部录数后一次确认更新库存，允许本人盘点、本人过账；重复提交不重复改库存。 |
| 班次现金差异 | 可以直接处理自己操作或关班的班次，保留差异原因和处理记录。 |
| 培训／寄售结算 | 核对账单后一次操作完成提交、确认和结算；可以处理自己创建的账单。寄售结算仍需真实付款凭证。 |
| 青少年培训规则 | 两种管理员均可一次创建并发布；历史草稿也允许原创建人发布，按配置时间生效。 |

小程序同步调整按钮、说明与确认弹窗。执行前保留一次必要确认，管理员执行成功后以短提示和状态刷新反馈，取消重复的结果确认。账单保留生成与查看步骤，方便核对金额。

## 实现与恢复

- 后台统一使用 `common/auth/admin-execution.ts` 判断管理员直接执行资格。小程序采用对应角色判断，后端独立校验权限。
- 继续复用各领域原有的入账、退款、冲正和状态转换命令，保留审计、库存核对、账期校验、支付凭证及并发保护。
- 自动串联的步骤使用稳定、区分阶段的幂等键。部分步骤失败时，用原命令重试可从剩余步骤继续。
- 活动取消先提交取消事务，再执行退款。失败会明确提示“活动已取消、部分退款尚未执行”；原操作重试只处理仍待执行的退款，财务退款列表也保留处理入口。
- 微信退款仍以支付渠道的实际结果为准，自动执行不代表立即到账；已批准或处理中的退款继续使用现有派发和恢复机制。
- 仅简化本轮八类工作流；其他角色的访问范围、库存变更校验、已关账保护、真实到场和课次时间条件均保留。
- 模拟服务同步了直接执行流程，并验证新增与已有退款合并处理及范围隔离。

- 类型检查、后端构建、H5 构建、微信小程序构建通过；微信包检查及位置接口检查通过。
- 新增测试覆盖：两种管理员权限、其他角色限制、自己创建的单据、阶段失败恢复、重复记账防护、活动退款范围、既有部分退款及重试。
- 375×812 浏览器验收：管理员从自己的培训草稿一次确认结算，弹窗关闭、状态更新，不出现二次结果确认。
- 812×375 横屏无页面横向溢出；减少动态效果模式可用，浏览器无运行错误。截图及可重复执行脚本见本目录。

- 既有活动事务测试的组合夹具隔离退款执行，以保留原有取消事务场景；新增退款执行服务测试单独覆盖自动执行、范围与失败重试，不将夹具替代支付渠道集成验收。
