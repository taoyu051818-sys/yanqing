# 场地审查第二轮修复（2026-09-19）

后续工程收尾已完成，见 [独立历史、营业时段与异步合同改进](../2026-09-19-availability-hardening/README.md)。以下保留上一轮当时的实现与验证记录；其中审计依赖和历史营业时段边界已由后续改进替代。

对应 `docs/audits/2026-09-19-new-features-round2` 的三个问题。仅本地开发与隔离测试，未部署、未上传微信版本、未修改生产数据。

## 修复结果

1. **旧表单覆盖新数据**：管理接口返回 `updatedAt`，编辑必须提交所读取的时间作为 `revision`。在场地行锁内校验，版本失效返回409；不再静默覆盖停用、用途等设置。版本时间单调递增，防止同毫秒写入重用版本。前端保留被拒绝的草稿，固定底栏提供重新加载按钮，并明确提示重新加载会替换草稿。重新加载不会自动保存。
2. **删除影响历史统计**：经营报表与老板摘要共用场地生命周期读取逻辑，利用已有场地审计还原启用、停用、恢复和删除生效时间。容量按对应开放区间计算，历史预约不再按当前可售场地过滤。删除后已有预约仍计入实际占用，同时不再虚增后续空场容量；重叠预约仍按时间并集计算。
3. **页面退出后迟到回调继续导航**：组合逻辑增加页面生命周期与操作代次校验；每次请求完成和刷新完成后都检查，失效操作不更新界面、不提示成功、不触发后续导航。覆盖删除、场地保存和球馆设置保存；旧账号操作的 finally 不会清除新操作的保存状态。

## 范围与上线注意

- 场地编辑接口现在必须带 revision，因此后端和小程序需要配套更新；旧客户端不会无版本覆盖数据。
- 本轮无需额外数据库字段；完整待发布改动仍包含前一轮 `20260919000000_court_soft_delete` 迁移，上线时应正常执行。
- 可还原的场地启停历史来自已有审计，绕过业务接口直接改库且未留审计的历史无法凭空恢复。历史营业时段仍沿用现有时段配置口径，本轮未增加营业时段历史快照。
