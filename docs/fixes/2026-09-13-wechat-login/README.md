# 微信提审：登录与游客浏览整改

日期：2026-09-13。依据：用户提供的三张审核驳回截图。本轮已修改本地代码并验证，没有部署服务器、上传微信包或重新提交审核。

## 三条原因及对应修改

| 驳回原因 | 当前修改 |
| --- | --- |
| 默认自动同意协议 | 删除“登录即表示同意”。登录页复选框每次进入默认未选，只有主动勾选后才调用登录。协议和隐私说明可打开现有风格的可滚动弹窗；阅读、关闭弹窗不会自动勾选。 |
| 活动页未浏览就强制登录 | 活动 tab 不再触发登录跳转。后端增加 `GET /api/v1/games/public`，开放已有安全字段投影的 `GET /api/v1/events`，游客可以浏览列表和详情。个人报名、成员名单及写操作仍要求登录。 |
| 登录没有有效取消/返回 | 首屏增加“暂不登录，继续浏览”，协议窗口可选择“不同意，继续浏览”。取消清理原登录目标；从公开详情进入时返回原详情，从“我的报名”取消后切回“找活动”，从受保护页面或直接打开登录时返回首页，避免再次触发页面登录守卫。离开时撤销尚未结束的登录请求，忽略迟到的成功响应。 |

头像昵称不再出现在登录后的必经步骤中，保留“我的—资料与设置”的主动完善入口。微信登录本身只使用登录凭证，不申请手机号、头像或昵称。未同意时只显示就地说明，不反复弹窗。

## 实现边界

- `apps/miniapp/src/pages/login/`：登录表单、可取消的授权尝试和协议弹窗。
- `apps/miniapp/src/utils/member-navigation.ts`：公开活动导航、取消与返回策略。
- `apps/miniapp/src/pages/community/index.vue`：先加载公开信息，再按登录状态同步个人报名。账号退出/失效立即移除私人字段，公开内容仍可浏览，保留已有异步请求归属检查。
- `apps/miniapp/src/services/api.ts`：公开活动与可选账号刷新发生 401 时不强行重启到登录页。通用受保护请求的默认处理不变。
- `apps/api/src/games/catalog/public-game-list.query.ts`：只读取已发布球局元数据和人数统计，复用公开字段选择；不读取个人报名、订单或联系方式。
- `apps/api/src/events/catalog/event-catalog.controller.ts`：仅列表增加公开标记，管理、报名和个人记录继续受认证保护。
- Mock 路由同步同一公开列表契约，匿名结果不包含模拟会员的个人报名。

未新增数据库迁移。原有工作区中的其他修复保留，不能把当前所有未提交文件都视作本轮改动。

## 提审前发布顺序

1. 先部署后端，使新的游客球局接口及赛事公开列表生效；旧客户端的个人球局接口保留。仅更新前端会导致新接口不可用。
2. 核对并完善运营方协议内容、真实主体和联系方式；本轮没有虚构法律主体或联系电话。微信公众平台中的用户隐私保护指引需要与实际调用能力、资料收集用途及页面文字保持一致。当前弹窗说明不代替平台后台配置，也不是完整法律合规结论。
3. 编译并上传新微信版本，使用新体验版进行以下真机验收。旧审核包不会随着服务器更新自动替换。
4. 验收后重新提交审核，并提供以下整改说明。

## 真机验收步骤

1. 清除体验版缓存或用未登录的新微信账号进入小程序，点“活动”：应直接显示日常球局和金羽积分赛列表，无登录弹窗。
2. 从列表及好友分享卡片分别进入球局、赛事详情：应能阅读时间、费用、活动说明。
3. 主动点“登录查看我的报名”或报名相关按钮进入登录页：协议应未勾选。不勾选点登录，只显示说明，不调起微信授权。
4. 打开两份协议，滚动查看内容，关闭后仍未勾选。点“不同意，继续浏览”，应回到公开内容且不再次弹登录。
5. 点“暂不登录，继续浏览”：从详情进入应回到同一详情；从受保护页面进入应回首页。重复操作和重进活动 tab，均不应被自动拦回登录。
6. 主动勾选并完成微信登录，应回到预期业务页面，不再要求先填头像昵称。随后验证正常报名、支付与订单查询；此步骤需要真机和实际用户操作，本轮未进行真实支付。
7. 登录请求等待时返回/取消，随后网络恢复，应留在浏览页面，不能被迟到响应重新跳转。退出登录后再次进入，协议仍需自主勾选。

## 可用于重新提审的整改说明

已整改登录与隐私交互：活动列表及详情支持未登录浏览，仅用户主动使用报名、个人订单等功能时提示登录；协议默认不勾选，可阅读后自主同意；登录页及协议窗口提供明显的取消/拒绝入口，取消后可继续浏览且不会反复弹出登录；登录不再要求先填写头像昵称。
