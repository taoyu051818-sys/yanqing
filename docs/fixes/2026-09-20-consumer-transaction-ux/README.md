# 会员端信息收拢与经营端订单流水

实施日期：2026-09-20～21。对应 `docs/audits/2026-09-20-consumer-transaction-ux/README.md` 的分析。

## 本轮行为

经营台新增「订单与流水」，常用业务与日常营业均可进入：

- 订单：默认今天，支持全部业务/状态、日期、订单号/会员姓名/手机号、支付方式查询。使用日期和下单日期分开选择。分页后进详情，返回仍保留已加载记录；退款状态即时更新。
- 收支流水：按真实发生时间分日展示，外部微信/现金收付款与账户变动分开。财务、管理员可看全馆账户变动；前台仅看外部收付款。汇总覆盖当前筛选的全部记录，不只计算当前页。
- 退款：默认跨日期的待处理、处理中、失败记录；也可查历史成功退款。按退款申请时间查询，不受原订单创建日期影响。
- 详情：固定退款入口，沿用既有退款命令及权限。管理员、超级管理员直接退款只确认一次；前台申请和财务审批的授权不变。可退金额由服务端结合已退款、进行中退款和培训剩余预付金额计算，执行时再次校验。
- 筛选弹窗关闭不清空列表；搜索输入提交后才查询。无记录和读取失败分开显示。

会员端：

- 首页优先呈现下一项订单安排；球馆信息收拢为可展开行。待付订单按有效期限筛选，已付款安排按实际使用时间选取。
- 订场默认显示今日尚未开始的时段，可切换全天；时间列固定。管理员代订继续允许既有特殊订场规则。游客仍可看预约情况，不因浏览主动登录。
- 订单列表改为时间、标题、金额和状态；付款、取消、退款历史进入独立详情。支付方式在可关闭弹窗中选择，支付/退款入口固定底部。
- 课程目录与选学员/班级、课程退费详情分开；同一页面路由通过明确详情参数加载单个对象。
- 活动入口收拢，报名详情独立进入；赛事展示真实占位队数与剩余队数，赛制规则按需展开；球友名单先展示前八位，支持展开全部。
- 充值与开通会员分开选择，选中方案后再通过底部按钮下单；钱包概览与完整分页历史分开，羽球币/积分按需展开。
- 卡券分可用和历史；小店购买在商品弹窗内选数量；资料、隐私与账号进入各自页面。

## 数据口径与实现边界

新增读取端点：

- `GET /orders/admin/ledger`
- `GET /orders/admin/refunds`
- `GET /orders/me/ledger`
- `GET /orders/me/next`

订单查询复用 `/orders/admin/all`，增加日期及支付方式条件；已有详情及支付/退款写接口继续使用。新增共享流水响应类型，后端查询按 `timeline` 目录拆分日期/游标、SQL 来源、服务与控制器。

日期按北京时间的 `[开始日00:00, 结束日次日00:00)`。支付发生时间使用 `paidAt`，退款使用 `completedAt`，申请队列使用 `requestedAt`，账户变动使用自身 `createdAt`。流水与退款用时间+ID游标；汇总与当次列表在可重复读事务中读取。

已经退款的原收款仍保留在收款历史。未完成/失败退款不计作已退款，余额消费不重复计作外部收款；余额、羽球币、积分分单位，不汇总成一个现金数字。冻结/解冻保留记录但不进入增加/减少合计。

本页展示系统已记录的外部收退款和账户变动；供应商、教练等业务结算仍在原财务模块，不推断为已经银行付款，也不把本页称为完整银行现金账。报名余位为已占位口径，包含有效待支付报名；提交仍由既有并发控制保证容量。

## 快速人工验收

1. 游客打开订场，确认能查看日期及预约状态，没有自动登录弹窗。
2. 会员打开订单列表，进入一笔待付款订单，打开/关闭付款弹窗，确认订单未被取消。
3. 进入充值页选方案；只选择时不下单，点底部按钮才生成订单。
4. 管理员进入经营台「订单与流水」，搜索会员，翻到第二页进入详情；一次确认退款，返回后检查原筛选和记录状态。
5. 切换外部收付款与账户变动，对照今天实际收款、退款；切到退款历史查看旧订单的新退款。
6. 打开钱包明细，选择日期并翻页；退出登录后确认个人记录消失。

复现：使用 mock H5 预览端口5198，执行 `verify-interactions.cjs`。脚本需要 Playwright 与本机 Chrome，不访问生产服务器。数据库组使用显式本机 `*_test` 数据库：`TEST_DATABASE_URL=... pnpm --dir apps/api test:core-lifecycle --group order_timeline`。
