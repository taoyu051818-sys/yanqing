# 高频业务交互简化：改价、代订、退款

日期：2026-09-22。状态：代码与本地验证完成，尚未部署服务器或上传新体验版。

## 使用变化

- **价格**：经营台 → 管理 → 球馆信息 → 营业设置 → 场地价格 → 修改价格。填写普通价与生效日期；新客价、备注等按需展开。核对适用时段、星期、前后金额和生效日期，一次确认即可完成配置，无需再手动停用旧版本、启用新版本。原新客价默认保留。场地价格仍按计价时段应用于全部可售场地，单独定价优先于默认价；本轮没有增加按单片场地定价。历史价格折叠，停用入口放在“其他操作”。
- **代订**：切换代订后选择会员；也可以从固定底栏重新选择或更换。场次表上再次点击已选场次可取消选择。核对会员、日期、场地和费用后提交；特殊代订在同一窗口填写原因。仍支持前台及管理员代订已占用、过时等场次。游客浏览不触发登录提示。
- **退款**：订单详情 → 直接退款／申请退款。窗口明确列出会员、订单、金额和退回方式。仅现金订单提醒先退回现金；微信和账户余额分别说明退回去向。管理员一次确认，无额外审批；前台的申请权限不变。处理进度从退款记录读取，不把受理当作到账。

## 实现与边界

新增 `POST /venues/price-rules/apply`，复用现有权限、幂等键和审计机制。旧价有效期与新价起始日期在同一 PostgreSQL Serializable 事务内衔接；同日起始时停用旧副本。来源版本使用更新时间校验，避免两人同时操作互相覆盖。适用范围冲突、审计失败均不留下半完成修改。历史订单金额快照不变。

价格视图、页面状态、表单校验、样式和后台应用命令分别放置。现有创建草稿和启停 API 保留兼容，未修改数据库结构。前端确认失败保留输入并复用幂等键重试。普通改价保留原适用范围与结束日期，其他范围用新增价格，避免隐式丢失原有覆盖。

上线顺序：先部署包含新接口的 API，再上传小程序包。旧小程序仍可使用原接口。

## 已执行验证

- 小程序全量：89 个测试文件，549 项通过；后续布局收敛后针对性复验 8 个文件、34 项通过。
- 真实本机隔离 PostgreSQL：7 项新改价集成测试和 5 项原价格测试，共 12 项通过。覆盖日期边界、幂等重放、并发竞争、适用范围冲突、审计写入失败回滚及权限。
- API 构建、小程序 TypeScript 检查、微信正式数据模式构建及包体／地图检查通过。
- 本地 H5 mock 交互验收：375px、320px，11 张截图；覆盖价格修改与结果、代订核对与结果、退款核对与结果，页面无横向溢出、无浏览器异常。脚本阻断所有外部 HTTP 请求。
- 微信真机、真实支付／退款、线上 API 尚未在本轮执行。H5 结果不能代替原生键盘与微信支付验收。

复现 UI 验收：启动 `VITE_DATA_MODE=mock pnpm --dir apps/miniapp dev:h5 --host 127.0.0.1 --port 5198`，运行 `node scripts/h5-core-task-ux-acceptance.cjs`（需 Playwright 和本机 Chrome）。数据库集成测试显式使用本机且名称以 `_test` 结尾的 `TEST_DATABASE_URL`，先执行迁移，再运行 `test/apply-venue-price.integration.spec.ts`。
