# 岗位操作减负与版本核对（1.0.11）

## 问题与变化

原先高频入口被待办挤到下面，试听缺课次时要离开表单自行寻找配置；代订成功后信息不足，退款已受理但订单刷新失败时仍可能展示再次退款入口。此前源码、服务器更新和微信体验版选择未形成统一的可核对记录。

- 前台首屏为代订、订单、预约试听；教练为今日课表、试听跟进、学员档案。保留完整业务与管理导航。
- 管理员和财务今天页显示实际收款与场地预约率，分别说明预收及预约小时口径。错误、未加载和实际零值分开；近七天迟到响应不能覆盖今日数据。
- 试听按学员、课次、确认组织。课次显示班级和时间，缺课程/班级/课次可直接补齐；子页返回使用实际创建的记录 ID，保留原学员和备注。刷新不再将失效选择替换成第一项。
- 新建课程和班级减少一次重复确认；不限仍直接可选。排课备注选填，场地占用核对保留。
- 代订结果显示会员、场地、时间和金额；明确选择同会员续订或换人。每笔新单清除场次，换人同时清除会员与优惠。响应丢失后的重试保留原核对命令，不因库存刷新变为特殊代订。
- 已受理退款独立于订单刷新结果；同步到同一退款记录前禁止再次发起。重新进入页面仍以服务端查询为准。支付和退款命令使用共享类型。
- “我的 → 关于金羽会员”游客可访问，显示微信实际版本、构建标识，可复制用于反馈。连接检查不宣称已更新到最新版。

## 工程边界

未增加数据库迁移，未改变管理员/前台权限、代订会员本人付款原则、退款渠道或账务规则。小程序页面按现有样式与公共弹窗组件实现。生产发布的 API 与小程序使用同一提交，服务器部署先于客户端上传。

同依赖、同数据库结构的 API 发布复用不可变依赖文件，候选版本构建产物仍独立；依赖/结构指纹不符时禁止激活，禁止在已发布版本中原地安装依赖。发布仍执行备份恢复、实际候选程序演练及健康检查。

`pnpm release:miniapp:prepare` 强制 remote 构建，将产物复制为独立快照并执行原生 WXSS 检查；`upload` 只上传该快照，核对源码、包摘要、AppID、版本和线上 API 提交。两个命令使用同一发布锁，等待服务就绪后再次核对快照，避免并发构建覆盖待上传文件。上传回执不能代替微信后台选择体验版或真机验收。

## 验证入口

- `pnpm verify`：运维、包与发布校验、共享规则、API、小程序、PC、E2E和正式构建。
- CI 额外运行完整隔离 PostgreSQL 业务矩阵。
- 本地 mock H5：`scripts/h5-training-prerequisite-acceptance.cjs`、`scripts/h5-workspace-role-delivery-acceptance.cjs`、`scripts/h5-booking-refund-delivery-acceptance.cjs`、`scripts/h5-release-identity-acceptance.cjs`。脚本禁止请求远端业务服务。
- 手机操作：[岗位真机验收表](../../acceptance-2026-09-26-role-workflows.md)。实际收退款、微信输入与体验版选择需要分别记录结果，不能以 mock 通过推定。

发布后机器回执位于 `output/releases/1.0.11-<提交>/miniapp-release.json`，统一包含服务器提交、上传状态及尚待确认的体验版/真机状态。交接时应同时提供该文件和填写后的手机验收表。
