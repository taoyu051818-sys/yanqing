# 登录会话与角色撤销

## 授权依据

JWT 的 `roles` 仅是签发时快照，不是请求阶段的最终授权依据。每个非 `@Public()` HTTP 请求在验证 JWT 签名和有效期后，都会按 `sub` 查询用户的窄字段身份快照：

- `status` 与 `deletedAt`；
- `primaryRole`；
- 当前 `UserRole.role`；
- 当前展示名称。

守卫使用数据库中的 `primaryRole + UserRole` 覆盖 token 内的旧角色，然后角色守卫再判断接口权限。因此停用、软删除、删除状态及角色变更会在下一次请求立即生效，无需等待默认 7 天 JWT 到期。

## 行为约定

- 用户不存在、状态不是 `ACTIVE` 或 `deletedAt` 非空：返回 401。
- 用户仍有效但当前角色不满足接口要求：返回 403。
- JWT 缺失、签名无效、过期或缺少合法 `sub`：返回 401。
- 数据库故障按服务故障处理，不伪装为 token 无效。
- 开发登录仍只在非生产环境开放，并同样拒绝停用或删除用户。
- 纯前端 mock 模式不请求 API，不受数据库身份复核影响；remote 模式与正式模式遵循相同守卫。

## 性能取舍

身份复核是一次基于用户主键的窄字段查询。当前不增加 TTL 缓存，因为缓存窗口会使“立即撤销”退化为“缓存过期后撤销”。如果未来请求量要求引入缓存，必须配套角色/状态变更事件主动失效，且验收仍需证明撤销后的下一次请求无法越权。

## 测试证据边界

`jwt-auth.guard.spec.ts` 覆盖公开路由零查询、无效 token、缺失 `sub`、数据库身份覆盖旧 token、旧管理员 token 的角色撤销、停用/删除/用户不存在及数据库故障。`auth.service.spec.ts` 覆盖开发登录拒绝停用/删除账户并按当前角色签发 token。单元测试不等同于真实数据库压测；上线前仍需在测试环境执行角色撤销与账号停用的端到端请求验收。
