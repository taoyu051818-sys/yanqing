# 按功能领域组织代码

本轮延续赛事、培训拆分，将剩余聚合业务服务改成按领域注入。HTTP 路径、角色装饰器、订单状态机、数据库结构与事务边界保持原样。没有拆微服务或新增 PC 功能。

## 后端导航

11 个聚合服务拆为 43 个 Nest 领域服务；控制器直接注入所需服务。领域服务负责依赖注入与公开调用入口，复杂事务位于同目录的 commands 文件，查询和政策分别放在 query/queries、policy 文件。

| 领域根目录（apps/api/src） | 业务边界 |
| --- | --- |
| inventory | 供应商、库位、采购收货、盘点、调拨报损、商品资料、库存流水 |
| inventory/consignment | 寄售销售/退款台账、查询、制单、复核结算 |
| games | 球局发布、主理人、报名候补、取消、完赛、奖励 |
| members | 会员目录及客户画像、线索跟进、漏斗分析、账户调整、推荐关系 |
| venues | 可售时段、封场、订场、签到履约、价格规则 |
| governance | 用户权限与状态、风险事件处理 |
| memberships | 会员产品、充值方案、购买和充值 |
| alliance | 商户、券模板、领券核销、结算 |
| training/trials | 试听预约、到场评估与转课 |
| orders | 查询、支付、申请退款、复核退款、未支付订单取消与到期清理 |

客户画像与会员档案查询独立；商品资料查询、修改与约束校验独立。不要将客户画像查询加回账户写入逻辑，也不要让商品目录承担出入库流水。

其他入口也已分离职责：

- `reports`：数据查询、报表定义、工作簿格式与导出装配。
- `work-items/domains`：按订单、退款、培训、赛事、库存等业务生成待办；入口统一过滤和排序。
- `dashboard/domains`：按场地、会员、培训、营销、库存、赛事、财务读取数据；入口组合展示结果。
- `reconciliation`：口径政策、对账快照、关账事务。
- `payments/wechat`：已验证的支付/退款通知处理、充值退款冲回；WechatPayService 保留签名、验签、解密与网络传输。
- `training/corrections`：查询、申请、批准、拒绝及政策。

`PendingOrdersService` 独占到期清理定时器及销毁生命周期。支付通知与资金流水继续通过原事务和订单状态机衔接，不因文件拆分多开事务。跨领域依赖通过模块 exports 和显式注入声明，禁止生产代码导入 test/support。

## 小程序导航

`apps/miniapp/src/packages/ops/pages` 的财务、库存、赛事、培训、治理、经营总览，以及 `pages/community`，已按业务区块拆成 37 个 `sections/*.vue` 组件。

财务、库存、赛事、培训按操作、加载和计算职责组织 composable。培训另有 5 个 `forms/*.ts` 管理课包、班级、课次、试听、监管规则表单初始状态。

页面保留生命周期、共享响应状态和组件装配；区块通过明确 props 接收数据，标量编辑用 `update:*` 事件和父级 v-model 回传。共享表单对象沿用原响应式对象。确认与错误仍由原 OperationTask 管理。样式保存在各页面的 page.css，页面和区块沿用原 scoped 样式。

不要为了缩短入口把全部状态合并成无类型的大对象。跨业务区块需要联动的状态由父级持有；领域操作只接收实际使用的依赖。页面装配仍有较多绑定，这是当前保留的复杂度。

模拟服务 `services/mock/router.ts` 只处理共用入口、鉴权及按顺序分派。原 171 个业务分支分布在 57 个路由模块中；规则在 policies，持久化状态按领域位于 state。保留原匹配顺序、延迟、到期处理及存储 key。培训与寄售的模拟接口也分别拆出了政策和命令。

## 核心接口合同与支付履约边界（2026-09-10）

`packages/shared/src/order-contract.ts`、`training-contract.ts`、`venue-contract.ts` 定义前后端共同使用的传输类型。订单列表/详情、订场响应、支付报价及返回值、微信拉起参数、场地可用性、培训产品/课次/报名已接入。小程序通过 workspace 依赖使用这些类型，不依赖 Prisma 或后端源码。

后端订单输出通过 `OrderProjectionSource` 接收数据库模型，再按白名单投影成 `OrderView<Date>`。培训查询、场地查询、支付报价及微信拉起参数也显式声明共享返回类型。HTTP 的日期由 JSON 序列化为 ISO 字符串；培训占场小时数保留 Decimal 的原有序列化方式，不改变财务口径。赛事报名里的精简订单另做显式白名单，不能把精简查询冒充完整订单。

培训页面的产品、课次、报名状态和相关操作/组件已使用这些合同。仍有试听、线索、治理等外围数据使用 any，应在对应业务迭代时逐项收紧，不用类型断言掩盖接口差异。

支付终结器只保留支付状态、幂等重放、金额核对、支付审计与即时履约协调。订单资源检查和支付后的业务操作，通过 `orders/paid-order-effects.ts` 顺序调用 11 个领域函数；具体场地、培训、报名、会员、充值、库存、推荐奖励及优惠券操作归所属领域。

调度器持有完整 `PaidOrderContext`；领域履约函数声明自己的窄输入，只包含实际使用的订单字段、付款信息和数据库操作。例如场地确认只接收订单 id 和 courtBooking.updateMany；推荐奖励对订单表只有 count 能力；商品出库只读取商品行 id、商品 id、名称和数量。会员权益、培训名单、库存分账等下游助手同步限制事务参数。

这些接口在 TypeScript 编译期限制依赖，并没有创建新的数据库客户端或运行时安全沙箱。调用方仍传入同一个 Prisma 事务，保持原检查顺序、统一回滚和幂等行为。领域履约函数不得引入 PrismaService、自行开事务、调用支付服务或回调总调度器。架构验收通过类型检查器约束数据表、操作方法及订单字段；真实数据库验收检查最后一步失败会回滚前面的订单/占场/支付，以及重试不会重复审计。

## 培训经营页的数据归属（2026-09-10）

`coach/data/teaching.ts`、`catalog.ts`、`trials.ts`、`youth-rules.ts`、`courts.ts` 分别创建并刷新所属业务的数据，通过只读计算引用交给页面。页面不再创建这些接口响应 ref；`actions/loading.ts` 只协调登录、权限、刷新、错误和后续定位，不接收整页的几十项数据状态。

`data/resource.ts` 复用读取生命周期：部分接口失败保留同一账号的可用响应、错误后可重试、忽略被新请求取代的结果。账号、角色或场地日期改变时，不展示旧作用域的数据；页面卸载时使未完成请求失效。这个助手只处理响应和刷新，不承担权限决策、付款或其他业务操作。

`actions/navigation.ts` 独立持有待办定位和管理视图参数。`actions/validation.ts` 保存操作原因、正整数及元转分的原校验函数；具体操作直接导入，不再通过页面重复转发。Nest 服务继续作为依赖注入和公开调用入口，本轮没有增加通用基类、注册工厂或事件总线。

试听、冲正、学员、规则及相关人员摘要增加客户端读取类型，对应请求、数据模块和展示区块已接入。这里只约束界面使用的字段，尚未把全部外围接口改成后端共同编译的共享合同。表单、部分操作上下文和其他经营页面仍有 any 与较多绑定，后续随所属业务迭代收紧。

## 会员订单页与培训读取合同（2026-09-10）

会员订单页的主体拆为四个流程模块：

- `pages/order/use-order-list.ts` 持有列表、详情定位、筛选及分页状态，处理刷新与追加请求的顺序和账号边界。
- `use-order-payment.ts` 持有支付报价、渠道选择及确认流程，继续使用现有 `createPaymentConfirmation` 查询服务端结果。原生微信支付返回成功后仍等待订单状态同步。
- `use-order-aftersales.ts` 管理取消与退款申请，使用同一份退款资格判断；赛事与培训仍进入各自业务入口处理。
- `use-order-clock.ts` 管理倒计时及到期刷新。页面隐藏时暂停计时/轮询，返回时恢复；卸载时销毁流程。

`order-action-scope.ts` 只负责同一页面的操作互斥与异步回调归属。它为操作保存账号版本和序号，旧操作结束不能清除新操作的忙碌状态。支付、取消和退款各自保留业务请求与反馈，不通过通用命令工厂转发。页面只装配这些模块及平台生命周期，展示规则集中在 `order-presentation.ts`，原 scoped CSS 原样移到 `page.css`。

共享包新增 `training-operations-contract.ts`，统一消课冲正与青少年监管规则的读取字段、状态取值和日期类型。后端查询和输出投影明确遵守 Date 合同，小程序使用对应 JSON 字符串类型；原客户端类型文件保留类型重导出，避免平行维护两套定义。监管规则投影接收不依赖 Prisma 的结构化输入，仅输出公开或管理字段白名单。

## 验证边界

球局会员列表、公开分享详情和登录后报名名单使用 `packages/shared/src/game-contract.ts`。列表只含当前会员报名摘要；公开详情只含公开信息与人数；名单接口单独返回当前会员订单入口。后端查询显式声明 Date 合同，小程序 API、社区列表及详情共用字符串日期合同，不平行维护本地定义。

- 原有 56 条赛事/培训路由合约，加本轮 150 条路由合约，验证真实 Nest 模块装配、角色限制及 HTTP 分发。路由测试替换业务返回值，业务本身另由单元和数据库测试覆盖。
- 架构守卫禁止恢复 11 个聚合服务入口，检查生产代码不依赖测试组合器。
- 单元测试中的旧类名组合器仅位于 test/support，实际委托给新领域服务，避免复制业务代码。
- 真实 PostgreSQL 验收继续使用 core-lifecycle-matrix.json，包括支付、占场、退款、报名、权益、库存、结算与异常事件。
- 小程序无 Intl 环境下的真实 setup 初始化验收支持新拆出的本地模块，并验证业务页不会因模块加载白屏。

自动化不能代替微信真机分享、登录和真实支付验收。现有 any 类型、部分较长的页面装配、历史 PC 原型与种子数据文件仍在，不能据此宣称整个项目已没有设计债务。
