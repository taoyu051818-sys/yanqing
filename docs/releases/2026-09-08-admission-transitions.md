# 签到与主理人审批并发修复（2026-09-08）

## 业务变化

- 球局和赛事签到不会覆盖已经完成的退款；球局退款递补候补后，原报名不能恢复签到并造成超员。
- 退款申请即使尚未改变报名状态，也会阻止新的签到。签到先提交后，会员仍可按原流程申请退款；全额退款完成后撤销入场资格。
- 重复扫码只保留一次签到时间和一条成功审计。并发冲突返回 HTTP 409，请刷新后重试；顺序重试返回原签到结果。退款中的已签到报名不再被当作可用入场凭证返回。
- 主理人申请、重新申请、通过和驳回统一受事务保护。审批不能覆盖另一项已提交决定，也不能消费驳回后重新提交的新申请。失败事务不授予/撤销角色，也不写成功审计。

## 实现与边界

新增 `common/state-transition.ts`，封装 Serializable 事务及 Prisma/数据库并发异常到 409 的映射，不自动重试审批。审批写入同时匹配 APPLIED 和 appliedAt，事务快照防止相同状态被再次使用时的旧操作覆盖。

签到先读取报名及订单，在同一事务中对订单取得 `FOR NO KEY UPDATE` 锁，再按报名原状态、订单关联及赛事取消标记条件更新。此锁与退款对订单的状态更新互斥，同时允许正常退款记录插入的外键检查；若订单在签到快照之后已改变，签到整体回滚。报名、签到时间、历史补录审计和签到成功审计一起提交或回滚。

不改变既有退款资格、金额、会员自主付款及候补递补策略，不改部分退款规则。无需数据库迁移，现有 41 项迁移保持不变；部署前后只读检查历史入场与角色一致性，不自动推测历史审批意图。

## 回归

新增 `admission-boundaries.integration.spec.ts` 的 17 项 PostgreSQL 回归：球局/赛事全额退款交错、候补递补容量、仅退款申请交错、签到先取得锁、重复扫码与时间稳定、审批/驳回相互覆盖、重新申请交错、并发初次申请及重复审批/驳回。使用真实服务和独立本地数据库，测试闸门仅控制真实查询的先后顺序。支付与退款走测试账户余额，无外部微信扣款。

新增 7 项事务错误映射单元测试，覆盖 Prisma ORM 冲突、PostgreSQL 原始 SQL 序列化/死锁，以及非并发数据库错误保留。数据库回归已加入 GitHub CI 的核心业务检查。

发布时核对 API 构建、仓库 lint、完整 API 单元测试、核心数据库回归、隔离数据库报表回归、HTTP 测试及 GitHub CI。实际结果与部署回滚位置存于本轮工作区验收记录。
