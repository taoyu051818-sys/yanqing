# 第十三轮修复：注销与履约、权益有效期一致

## 行为变化

- 部分退款且尚未履约的订单仍阻止注销。即使历史订单已有完成时间，只要关联预约仍为已确认、已签到或有效保留状态，也不会放行匿名化。
- 已完成履约的部分退款订单，以及全额退款并取消的预约，可以正常进入注销流程。
- 注销检查用同一个当前时间判断会员、券码是否自然到期，不依赖批量更新 EXPIRED 状态。会员保护所有未到期订阅，包括未来续费；券码同时检查自身及模板的截止时间。
- 商户或券模板暂时停用、权益尚未开始，都不会被当成已经到期。原有余额、待审批调整、未完成付款退款等阻塞条件继续生效。
- 注销完成前仍在 Serializable 事务内重新检查条件；本轮不修改订单、退款、订阅和领取历史。

## 验证

- 新增 `privacy-lifecycle.integration.spec.ts`，13 项 PostgreSQL 回归测试通过，覆盖实际支付、部分退款、履约和注销审批链路，以及到期临界点、未来权益与临时停用。
- 在全新隔离数据库 `privacy_release_test` 中应用 42 个迁移，注销、会员培训权益、运营边界三个套件共 62 项通过。
- API 常规测试 837 项通过，API 构建、lint 和 diff 检查通过。lint 仍有原有 `orders.journey-closeout.spec.ts` 未使用导入警告。
- 新测试已加入 GitHub Actions 的串行数据库回归步骤。

首次扩展回归复用了审查数据库，一个既有跨等级并发建单测试未得到预期 409；单独复跑该用例通过，但该数据库上的旧培训结算记录影响了另一个测试。因此最终结果以全新数据库上的 62 项测试为准，没有通过修改业务代码或放宽断言消除这些测试异常。

本轮仅完成本地开发、验收与代码同步，尚未部署生产；所有支付和注销验证均使用本地合成账号及模拟支付，没有操作真实会员账号。
