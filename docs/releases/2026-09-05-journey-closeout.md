## 二、待付款订单与支付预检

- 场地、球局、培训、会员、充值、商品提供待付款取消入口；赛事保留报名域的退出入口，避免绕过队伍和退款规则。
- 非场地通用购买保留15分钟；场地、赛事、培训已有资源保留期优先。返回统一支付截止时间，页面倒计时，服务端启动时及每30秒扫描。
- 取消/过期同步释放对应场地、球局席位、赛事队伍或培训名额；未付款会员资格取消；未到账充值和未售商品不会凭取消产生资金/库存变化。
- 取消要先确认归属和状态；微信支付处理中须完成远端关单，再进入事务复查。关单失败或并发支付变化时不能直接释放资源。
- 新增逐订单支付方式预检：可用余额扣除冻结部分，明确渠道禁用原因；充值不能用已有余额支付；币值按服务端当前参数报价。
- 提交时重新验证金额、状态、库存、券范围与币值报价；客户端报价只是核对依据，不是支付授权。失败可重新同步支付方式。

## 三、商户券政策（按用户确认执行）

**已有商户券也禁止直接抵扣订场，不采用旧券继续可用的兼容方案。**

1. 新增 CouponTemplate.allowVenueBooking，默认 false；既有模板同样为 false。
2. 普通商户券仅用于所属商户；管理员可以在“设置适用范围”中显式开启订场，并说明依据、留下日志。
3. NEWCOMER 专用券保留已有新客业务规则，不等于普通商户券自动开放订场。
4. 券包显示范围，订场列表排除不适用券；服务端建单和付款都复核，不能只隐藏界面。
5. 已付款订单保留原成交记录。尚未支付且使用了现已禁用商户券的旧订场订单，提示取消后重选优惠，不能按旧折扣继续付款。

迁移：20260905180000_coupon_booking_scope。全新隔离 PostgreSQL 已成功执行全部33个迁移；另在隔离事务中模拟已有模板，验证迁移后旧模板和新建模板均为 false。临时数据库服务已停止。
