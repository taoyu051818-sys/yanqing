# 小程序用户旅程低摩擦改造

日期：2026-09-05。范围：会员高频旅程与前台履约；保持既有账户、权限、价格、退款审批和审计规则。本轮不修改数据库结构或服务器业务接口。

## 结论

这轮不是“删除所有弹窗”，而是把正常流程从临时提示迁回业务页面：选择 → 核对 → 确认 → 看到下一步。资金操作、退出报名和履约关单仍必须主动确认。

使用 ui-ux-pro-max skill，沿用现有球场绿视觉体系，应用渐进展开、原因选项、就地错误、忙碌锁定和小屏换行。没有新增界面库或第三方资源。

## 已改造的旅程

| 用户要做什么 | 原来卡在哪里 | 现在怎么操作 |
| --- | --- | --- |
| 充值、开通会员 | 创建订单后仅弹出成功提示，要自己找订单 | 方案显示本金与赠送分账 → 点击下单 → 自动到该订单付款；充值完成后可直接查看余额明细 |
| 购买商品 | 弹窗手填数量，再弹出订单号 | 页面内加减数量、显示小计、库存上限 → 下单 → 对应订单付款；无库存禁止购买 |
| 支付订单 | 四种支付方式挤在操作菜单，不知道可用余额和限制 | 页面内选择支付方式、余额提示、核对金额后确认；充值只允许微信；模拟和真实微信支付明确区分 |
| 订场使用优惠券 | 手抄、复制券码 | 直接选择我的券包；也可从券包点击“使用此券”带入订场，不在跳转地址暴露券码 |
| 领取券 | 只能打字输入 | 微信端新增扫码识别后确认领取；保留低频手输方式，提交锁定，错误就地显示 |
| 课程报名 | 先后弹出学员、班级选择，再弹窗找订单 | 在所选课程内核对班级与学员；唯一选项预选，多选时用选择器；新建学员后继续当前课程；创建订单直接付款 |
| 课程退费 | 连续核对范围、填金额、填原因 | 同一表单显示可退上限、原付款构成；默认全部可退余额，可改部分金额；点选原因后明确提交，进入对应订单看审核进度 |
| 普通订单退款 | 弹窗输入原因，错误后重新填 | 常用原因选项，其他原因才输入；失败保留内容；重复提交锁定；零可退金额不提供无效退款入口 |
| 赛事退出 | 填原因 → 确认 → 成功三个弹窗 | 赛事卡片内说明候补/未付/已付不同影响 → 点选原因 → 明确确认 → 刷新报名与退款状态 |
| 邀请好友使用 | “复制邀请码”与分享并列，接收方要理解代码 | 微信端优先发送卡片；H5 优先系统分享完整链接、不支持时复制完整链接；旧邀请码补录折叠 |
| 前台确认完成/未到场 | 手填弹窗说明 | 在具体订单内选择核实原因或补充说明 → 确认关单 → 订单与日志更新；重试沿用本次核实时间 |

### 没有改变的安全边界

- 选券仅排除明确无效、过期、停用的券。最终适用时段与价格由服务器核验，没有前端擅算优惠。
- 充值本金、赠送余额、羽毛球币不合并。羽毛球币兑换比例仍由服务器参数决定，不硬编码。
- 退款“申请提交”不代表已到账。赛事已付退出继续遵守审批完成前占位、禁止签到的既有规则。
- 没有自动创建订单或扣款；忙碌按钮防止连续点按，已有幂等协议继续生效。
- 邀请链接只携带不透明邀请凭证，不带手机号、用户 ID；打开分享不会自动代替用户完成支付或赛事报名。
- 本地回归只在独立浏览器的 mock 存储中运行，阻断所有外部请求；不清空使用者浏览器数据、不写真实订单、不发起真实支付。
