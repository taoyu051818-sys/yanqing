# 赛事与培训按功能领域拆分

## 结果

删除原 `EventsService`（2,525 行）、`TrainingService`（2,421 行）及两个聚合控制器。改为 16 个领域服务、13 个领域控制器，按赛事管理、邀请、报名、比赛、奖品及培训课程、学员、报名、排课、考勤、消课、冲正、结算组织目录。控制器直接调用所属领域服务，模块只负责装配。

本轮拆出的服务最大 599 行。共用规则显式传入数据库或事务依赖，保留原有事务范围和业务校验。订单、退款、微信支付调用方更新为新领域路径。没有页面、数据库结构、API 地址、角色权限、管理员/前台代订绕过规则的变更。

完整领域边界见 [核心架构说明](../architecture/core-order-lifecycle.md#活动与培训模块边界)。体验课服务和消课冲正命令仍分别约 961、767 行，未声称所有大文件均已消除。

## 验证

- API 构建通过；相关源码、架构及模块装配测试的 oxlint 通过。
- 原业务回归与架构、PC 会话契约共 860 项通过（全量中 853 项先通过；修正遗留结算测试的旧控制器引用后，该文件 7 项单独复跑全部通过）。
- 本地隔离 PostgreSQL：42 项迁移成功，核心矩阵 286 项通过：shared 238、training 13、reporting 13、boss_events 8、amounts 14。
- API e2e 共 9 项通过；新增 3 项逐一覆盖拆分前 56 条路由的元数据、实际 HTTP 分发、受保护接口的普通会员拒绝。
- 对比拆分前源码，59 个服务方法和 9 个抽取的共用策略方法在显式依赖替换后，规范化 JavaScript 方法体一致。
- 原测试通过测试目录内的组合器调用真实领域服务，生产构建排除组合器；架构测试禁止生产源码引用它们。

模块装配测试替换业务方法返回值，数据库验收运行真实业务代码；外部微信接口使用测试替身。上述验证不代表真机分享和真实资金支付已验收。本次为代码重构，未部署线上。
