# 2026-09-10 领域依赖与培训数据归属

## 变更

- 9 个领域文件中的 11 项支付履约操作改为局部窄输入，限制可用的数据表、操作方法、订单字段和支付字段。同步缩小会员权益、培训名单及商品库存助手的参数；调度顺序和同一事务保持原样。
- 培训经营页的数据由教学、产品配置、试听、青少年规则和场地模块分别持有和刷新，页面负责协调。待办定位单独持有路由状态。
- 多个接口共用带请求序号和账号作用域的读取逻辑：局部失败不抹掉同账号的成功数据，旧请求不能覆盖新请求，账号/角色/日期变化隐藏原数据，离开页面后不回填。
- 试听、冲正、学员、监管规则及人员摘要增加客户端类型。三个已有校验函数提取为直接复用的纯函数，移除页面重复转发参数。
- 现有 Nest 服务仍承担依赖注入；没有新增通用 CRUD、基类、事件总线或微服务。

## 验证

- 后端单元测试 865 项通过，包含新增的类型依赖约束；接口 e2e 12 项通过。
- 本轮真实 PostgreSQL shared 组 239 项通过，覆盖订场、支付、报名、会员权益、库存、优惠券、退款等；验证履约末尾失败时整体回滚及重试幂等。数据库仅使用临时本机测试实例，完成后已关闭。
- 小程序全量 338 项通过；新增 13 项覆盖响应乱序、局部失败与重试、权限变化、场地日期切换、登录失败和卸载后的未完成请求。
- API 构建与 lint、小程序类型检查、H5/微信构建及微信分包检查通过。
- 归一化 JavaScript 语法树确认 12 个后端业务源文件的可执行逻辑一致；3 个迁移校验函数的函数体一致。

## 边界

没有数据库迁移，不修改支付金额、订单状态机、退款政策和管理员/前台代订绕过规则。依赖限制是编译期约束；领域函数仍依赖 Prisma 的操作类型，尚不是数据库无关的纯领域层。

本轮同步 GitHub，不部署线上。微信外部支付在自动化中使用测试替身；本轮没有执行微信真机或真实收付款验收。
