# 活动候补、奖品与培训结算职责拆分

订单取消、退款和微信回调原本从大型赛事、球局服务中导入候补函数，使资金流程加载活动管理代码。此次将候补领域规则独立，活动操作和订单流程调用同一入口；同时把赛事奖品和培训结算从主服务抽出，减少修改时需要检查的职责范围。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `events/event-waitlist.ts` | 赛事超时未支付席位释放、按队列递补及新订单绑定 |
| `events/event-registration-policy.ts` | 赛事席位状态、付款期限及退出退款标识 |
| `games/game-waitlist.ts` | 球局候补领取、创建待支付订单及审计 |
| `games/game-registration-policy.ts` | 球局容量、席位、报名与支付窗口规则 |
| `events/event-prizes.ts` | 奖品查询、发放、签收、库存扣减、权限及幂等核验 |
| `events/event-command-support.ts` | 赛事命令的文本规范化、幂等键长度校验及编号等公共辅助逻辑 |
| `training/training-settlements.ts` | 培训经营汇总和结算单完整状态流程 |

原 `EventsService`、`TrainingService` 对外方法继续转发到独立命令，控制器和返回结构不变。候补函数沿用调用方事务；奖品及结算保留原事务、并发条件、权限和审计。管理员、前台代订绕过策略未变。没有数据库迁移、依赖变更或前端修改。

主服务行数变化：赛事 4,539 → 3,792；球局 2,013 → 1,900；培训 3,602 → 3,188，合计减少 1,274 行。移出的职责保留在对应领域文件中。赛事报名邀请、赛程比分以及培训排课、消课纠正仍可继续按流程拆分。

## 验证

- API 源码及架构测试 849 项通过，订单会话合约测试 10 项通过，共 859 项。
- `test:core-lifecycle` 全部分组通过，共 286 项真实 PostgreSQL 集成测试：shared 238、training 13、reporting 13、boss_events 8、amounts 14。
- API e2e：6 项通过。API 构建、变更文件 oxlint 及差异空白检查通过。
- 22 个迁移的函数体经 TypeScript 转译后进行语法树对照，显式数据库依赖及原私有辅助函数引用替换之外，执行逻辑一致。
- 新架构检查遍历指定核心入口的静态相对导入/导出链，阻止订单、候补、奖品及结算实现重新依赖赛事、球局、培训大服务。

回归中发现球局规则引入 DTO 会带入装饰器运行环境依赖，已把容量常量归回领域规则，由 DTO 单向引用；原有纯规则测试随后通过。

数据库验收仅使用本机新建的隔离测试库，不访问线上数据。外部微信接口仍使用测试替身。本轮为源码重构，尚未部署线上。
