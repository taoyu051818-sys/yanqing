# 培训修复发布方案

1. PR 与主分支 Verify 均通过后，从同一提交构建带完整校验清单的 API 发布包。
2. 服务器创建独立 release；本次锁文件含工作区调整，按候选冻结锁文件独立安装 API/shared 依赖，禁止复用旧 node_modules。安装后重新校验文件清单。
3. 校验既有迁移全部不变，唯一新增迁移为 20260922103000_training_all_audience，只为枚举添加 ALL。
4. 持有运维互斥锁，旧工具备份生产库并实际恢复验证。在另一临时库应用新迁移，比较全部业务表行数与内容摘要，确认历史数据完全不变。验证枚举 ADULT/YOUTH/ALL。
5. 在恢复库对新版编译产物执行权限、订单支付退款、数据库中断恢复演练。成功后才迁移生产库；再进行新版备份、恢复、演练，生成标准 release receipt。
6. 用既有 activate 脚本切换，验证本机及公网 revision/readiness，更新独立运维工具指针。
7. remote 模式构建小程序，上传 1.0.10 开发版本并核对体验版标记。上传不等同于正式审核发布。

回退边界：枚举新增可保留，但一旦产生 ALL 课程不可将应用回退到不识别 ALL 的老版；优先前向修复，禁止删除新业务或回灌旧库。生产规则数值与预约生效时间保持不变，管理员可以通过新界面沿用配置并立即发布。
