# 2026-09-05 双打代填与微信搭档邀请

## 用户旅程

入口：活动 → 赛事 → 报名。旧的连续弹窗和“搭档生成授权码、队长粘贴”入口已替换为独立报名页。

1. **我填写两人资料**：一个已登录会员填写队名、组别、每位选手姓名及联系电话，确认已取得两人同意后提交。有名额时创建一笔整队待支付订单，队长统一付款；搭档不需要注册。默认提交人是选手一，也可取消“我本人是选手一”，只代为办理两位其他选手的报名及付款。
2. **微信邀请搭档**：队长填写本人姓名、联系电话、队名和组别 → 生成邀请 → 通过微信原生分享面板选好友 → 好友打开卡片查看赛事、邀请人昵称/头像 → 登录并填写本人姓名、电话，明确确认组队 → 队长返回页面刷新确认状态 → 提交两人报名并支付。
3. **返回继续**：队长待确认的邀请按当前账号和赛事保存在本机，有效期内返回该赛事报名可继续处理。缓存只保存邀请凭证与到期时间，不保存联系人资料。失效或撤回邀请提供重新填写入口。
4. **满员/取消**：满员时持久候补，不创建订单或提前收费。待支付报名可以从订单的“查看报名与取消”进入我的报名退出；取消释放名额及重复报名占用，允许重新提交。沿用赛事既有 15 分钟支付保留、候补晋级及超时关闭机制。

微信能力边界：不读取完整微信好友通讯录。使用原生 `button open-type="share"` 和 `onShareAppMessage`，由用户在微信分享面板选择好友。官方分享能力参考：[腾讯分享指引](https://cloud.tencent.com/document/product/1301/107818)。H5 提供复制邀请链接，不伪造微信好友列表，也不能代替真机分享验收。

## 数据及权限

- 联系方式按每位选手必填，当前支持中国大陆 11 位手机号，API 会规范化空格、横线及 +86 前缀。
- 参赛资料与登录账号分离：代填人名、手机号不会创建第二个 User，也不会因手机号相同就绑定、取得他人的账号身份。未注册选手的赛果保留在队伍记录中，不自动向一个臆造账号发积分。
- 仅代报名的付款人不占参赛账号位置、不领取两位选手积分；本人参赛时只向实际关联账号发积分。
- 同场赛事对有效报名、候补按手机号及已关联账号交叉检查，已取消/退款的历史记录不阻止重报。同名而不同手机号可报名；两名选手使用同一个手机号会被拒绝。该规则是重复资料检查，不是实名或手机号持有人认证。
- 分享标题含邀请人昵称和赛事名，沿用压缩后的比赛配图；落地页展示邀请人昵称及头像。URL 只含赛事 ID 和不可预测的邀请凭证。
- 公开预览不返回选手联系号码、另一位搭档的资料、账户 ID、订单 ID 或令牌哈希；已确认选手姓名仅在队长/搭档本人视角提供。普通会员不能调用管理详情；有赛事管理权限的岗位可点开联系资料，办理本次赛事。
- 邀请凭证在服务端只保存 SHA-256 哈希，最长 24 小时且不越过报名截止/开赛时间。接受邀请必须明确同意，打开卡片不自动报名；一份邀请只允许一位搭档确认、仅原队长提交，组别/队名不可被第三方篡改。
- 接受和提交使用数据库事务及条件更新，应对同时确认/报名；幂等键覆盖代填信息与付款人是否参赛。代填提交成功时，在同一事务内撤回本赛事该队长之前未使用的邀请卡片。
- 审计记录操作人、同意状态及动作，不写入电话号码或明文邀请凭证。旧版小程序的授权码 API 暂保留兼容，旧前端界面、无调用的 API 包装函数及对应样式已删除。

- 甲进入“活动→赛事→报名”，代填两人姓名和电话；乙不注册也能完成整队报名。核对金额是一队费用，不重复收取两次。
- 甲选择“微信邀请搭档”生成并发送卡片；微信分享面板可选好友，标题/配图正确，卡片打开到指定赛事的邀请页。
- 乙冷启动打开卡片，查看甲的昵称/头像；微信登录后仍返回同一邀请页，明确确认以后才成为搭档。
- 甲返回刷新状态，核对两人姓名后提交；乙点击过的同一卡片不能再被丙占用，非甲不能代为提交。
- 检查手机键盘、真机安全区、网络中断重试与分享返回；支付结果以真实微信支付回调及订单状态为准。
