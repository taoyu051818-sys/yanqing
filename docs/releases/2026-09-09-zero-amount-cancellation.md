# 第十四轮修复：零元活动退出与整场取消

## 行为变化

- 已确认的零元积分赛报名可直接退出，报名和订单在同一事务内取消，立即释放名额并按原有规则晋级候补；重复提交不会重复晋级或生成订单。
- 管理员取消整场积分赛或球局时，同时取消其已确认零元订单，避免报名已取消、订单仍显示已支付。
- 共享取消逻辑仅接受应付、实付、已退金额均为零且尚未完成的活动订单；如存在正金额付款证据或退款记录则拒绝处理并回滚。
- 保留成功的零元确认记录，不生成零元退款；撤销尚可撤销的关联推荐奖励，并记录订单取消审计。正常付费订单继续走退款审批。
- 小程序对免费报名退出明确提示“无需退款、释放席位并晋级候补”，付费报名继续提示退款审批。

## 验证

- 新增 PostgreSQL 回归套件 `zero-amount-cancellation.integration.spec.ts`，13 项通过，覆盖免费确认后的退出、整场取消、幂等重放、候补晋级、推荐奖励撤销、异常付款回滚，以及正金额退款对照。
- API 常规测试 837 项通过；API 构建、小程序类型检查与微信包构建、lint 通过。lint 仍有原有 `orders.journey-closeout.spec.ts` 未使用导入警告。
- 在全新隔离数据库 `zero_cancel_final_test` 应用 42 个迁移后，支付生命周期、报名边界、零元取消三个套件共 36 项通过。
- 新套件已加入 GitHub Actions 的串行数据库测试步骤。

扩展回归的前两次运行出现 5 秒测试超时，未结束的异步操作随后与后续用例产生事务冲突。最终在新隔离库串行执行，并通过命令行将测试及初始化时限调整为 30 秒，36 项全部通过；没有改动业务断言或生产事务配置。新增零元取消套件首次单独执行时，也已在默认时限内通过全部 13 项。

本轮不需要数据库迁移。测试使用本地隔离数据库和合成账号，不调用真实微信支付。仅完成本地修复与代码同步，尚未部署生产，也未回写历史异常订单。
