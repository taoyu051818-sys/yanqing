# 核心订单生命周期收拢验收记录

日期：2026-09-09。范围：小程序使用的核心后端、共用业务规则、验收入口；未扩展 PC 功能，未部署线上。

## 本轮变更

- 已有订单状态修改进入统一状态入口，声明支付、取消、签到、履约、退款、迟到付款补偿和课包冲正的合法路径。必须指定单个订单 ID 与原状态；条件更新失败由调用方处理或直接回滚，避免无条件覆盖其他操作。
- 普通取消、超时释放和无法履约的微信回调共用未支付资源释放规则。场地、优惠券、报名席位、待支付课包和冻结会员权益按所属领域处理，候补递补仍受原领域规则约束。
- 现金/余额退款批准与微信退款成功通知共用退款资源处理。原库存批次、课包余款与名单、会员续期、报名与候补、推荐奖励使用同一套政策；补偿退款不能回退从未授予的资源。
- 保留免费场地与免费活动的领域差异、退款审批、历史完成/未到场证据，以及管理员和前台代订的现有绕过权限。整场活动取消时，已有待审核退款的订单可以追加余额退款申请，无需再次改变订单状态。
- 新增状态写入架构检查、集成测试清单完整性检查，以及真实数据库中的状态竞争与三渠道退款验收。
- GitHub Actions 与本地共用 `pnpm test:core-lifecycle`。统计类验收自动创建并清理独立数据库；缺少显式测试库配置会失败。每个数据库用例允许 30 秒、初始化允许 60 秒，不修改生产业务事务超时或断言条件。
- 报表测试的事件复核用例改为各自准备订单证据；并发测试在被测操作提前失败时及时解除等待，避免一个测试失败引发后续用例缺失数据。

真实 PostgreSQL 验收合计 286 项，新增 15 项覆盖非法状态跳转、支付/取消并发事务回滚，以及微信、余额、现金的部分退款、全额退款与重复通知。普通测试新增 9 项保护状态入口及验收清单。

本机首次高并行运行出现资源争用和超时；最终普通测试采用两个工作进程。数据库 shared 与 training 分组在新建基础库完成，报表、老板事件和金额分组在各自新建临时库复验通过，临时库由统一入口清理。所有业务断言均保留。

外部微信接口使用测试替身；数据库事务、业务服务及通知处理执行真实代码。真机分享、微信登录、真实扣款退款与线上网络连通性未包含在本轮验收中。未改数据库结构，沿用已有 42 个迁移；未接触线上业务数据。

架构约定和后续执行流程见 [核心订单生命周期与验收约定](../architecture/core-order-lifecycle.md)。
