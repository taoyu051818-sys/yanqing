# 第十二轮修复：分次退币与零元确认

## 行为变化

- 羽毛球币退款按累计退款金额计算应退总币数，再减去同一会员、同一订单实际已退币数。使用整数运算，避免每次独立四舍五入导致多退或少退。现金与赠送余额仍按分精确退回。
- 退币以原支付扣币流水为依据，不受后来兑换参数变化影响；缺失有效扣币流水时停止审批并提示核对账务。重复审批不会重复入账。
- 零元订单完成原有权限、有效期、名额、库存和券范围校验后，在同一事务中确认订单与业务状态，无需调用微信或扣账户余额。支付记录金额为 0，标记为 `zero-amount`，不生成模拟微信交易号。
- 小程序零元订单显示“免费确认”，隐藏支付渠道选择，并反馈“订单确认成功”。非零订单维持原支付流程。

## 验证

- 新增隔离 PostgreSQL 回归测试 14 项，覆盖零元真实配置/模拟配置、未绑定微信与无钱包、旧客户端账户渠道、重复提交、越权、超时、过时报价、分次退款多退/少退、默认兑换比例、历史少退补足、扣币流水缺失和现金余额退款。
- 与支付生命周期、报名边界、账本边界共 59 项数据库测试通过。
- API 常规测试 837 项、小程序测试 278 项通过。
- API 构建、小程序类型检查、微信小程序生产构建与包体检查通过。
- API lint 通过；已有 `orders.journey-closeout.spec.ts` 未使用导入警告仍在。
- 新回归套件已加入 GitHub Actions，使用独立的本地测试数据库，避免修改其他套件的兑换参数。

本轮未部署生产，也未进行微信真机付款。零元确认通过严格拒绝零金额的微信接口替身验证。历史已完成的退款没有批量改账；旧流程若已多退，不会在下一笔退款中自动扣回，需要单独核账处理。
