# 架构改进与验证记录（2026-09-22）

本轮目标：落实验收矩阵、关键 API 类型、会员页面任务拆分、历史原型隔离四项改进。未变更经营权限、计价、支付渠道或数据库结构。

## 完成的改动

1. 核心验收矩阵增加 `training-batch.integration.spec.ts`，培训分组现在覆盖退费与名单同步、适用人群、批量签到和消课。架构检查从 9/10 恢复为 10/10。
2. 原 624 行 `services/api.ts` 改为 31 行兼容聚合入口，247 个操作分属 10 个业务领域文件。已有调用名称、路径和参数保持兼容。
3. 培训学员、购买请求、报名记录、公开赛事和会员优惠券使用明确类型；公开赛事、学员和优惠券投影在 API 端也引用共享返回契约。
4. 培训提取学员建档、课程购买、退费三个任务；订场提取场次查询/选择与优惠券任务；赛事报名提取队伍表单、授权和校验。任务拥有自己的状态与重置逻辑，页面保留路由和流程组合。页面样式相邻存放。
5. 学员建档、课程购买、退费及优惠券刷新增加发起会话检查，避免账号切换后的异步结果污染当前页面。优惠券刷新增加请求序号，旧错误不会清除新结果。
6. 经营台赛事加载上下文复用命名类型，文件从 554 行降至 264 行；避免重复展开 Ref 内部结构。
7. Next.js 原型迁入 `legacy/web`，拥有独立 package、配置和构建入口。移除原型中未应用到页面的 Google 字体初始化，消除其构建时外部字体下载依赖。
8. 补齐小程序构建对 PostCSS 的明确依赖，并修正 uni-app CLI 发布包缺失的依赖声明；H5 Docker 构建补上共享包清单与构建步骤。历史原型不进入生产 Docker 上下文。
9. 新增生产/原型依赖隔离、接口模块依赖方向检查，以及任务交互和请求归属回归。更新 README 和架构文档。

文件行数只是结构变化的辅助信息。培训、订场、赛事页面仍保留较长的模板；后续只在独立任务或稳定复用点上继续拆分，不以行数作为质量目标。
