# 客户线索、会员 360 与主理人申请验收

## 客户线索状态机

线索状态固定为：`NEW → CONTACTING → TRIAL_RESERVED → ATTENDED`，随后只能进入 `CONVERTED` 或 `LOST`；两个终态可归档为 `ARCHIVED`。普通跟进不能回退状态，也不能绕过转换/流失动作直接写终态。

线索保存来源渠道、来源活动、直接推荐人、负责人、下次跟进时间和 SLA 截止时间。跟进记录为只追加的 `LeadFollowUp`，系统不提供修改或删除接口，外键也阻止带跟进历史的线索被级联删除。

## API

| 动作 | API | 权限 |
| --- | --- | --- |
| 列表与筛选 | `GET /members/leads` | 前台、教练、管理员 |
| 创建 | `POST /members/leads` | 前台、管理员 |
| 认领 / 分配 | `POST /members/leads/:id/claim`、`POST /members/leads/:id/assign` | 前台、管理员 |
| 追加跟进 | `POST /members/leads/:id/follow-ups` | 前台、管理员 |
| 转会员 / 流失 / 归档 | `POST /members/leads/:id/convert`、`lost`、`archive` | 前台、管理员 |
| 会员 360 | `GET /members/:id/360` | 前台、教练、财务、管理员 |

列表支持关键词、状态、来源、负责人和 SLA 逾期筛选。创建、认领、分配、跟进、转换、流失、归档都写审计日志；转换必须关联已有 `MemberProfile`，不能把员工等非会员用户作为转换目标。

教练仅能看到分配给自己的线索，或已转换且属于本人任教班级的会员线索。教练关键词查询不搜索手机号，返回结果隐藏手机号；会员 360 只返回本人班级的培训上下文，联系方式、账户、订单、球局、赛事和券均不返回。

前台、财务和管理员的会员 360 包含最近订单、培训、球局、赛事、联盟券与五账户。该页面是经营服务视图，不替代订单、财务或培训领域各自的审批权限。

## 主理人申请

管理员可通过 `GET /games/host-applications` 查看待审批申请，通过原有 `POST /games/hosts/:userId/approve` 批准，或通过新增 `POST /games/hosts/:userId/reject` 填写必填原因后驳回。申请、批准和驳回都写审计；只有 `APPLIED` 状态可处理，批准会授予 `HOST` 角色，驳回会清理可能残留的 `HOST` 角色。

## 小程序 mock 验收

1. 用管理员身份进入“会员服务”，在“主理人申请”队列批准或驳回申请。
2. 切到“客户线索”，创建带来源和活动的线索；依次认领、分配、跟进推进、转会员或标记流失。
3. 返回“会员 360”先选择会员，再回线索执行“转会员”，检查线索进入 `CONVERTED`。
4. 切换教练身份，确认只能看到本人负责数据，手机号与账户等财务信息隐藏。
5. 切回管理员，确认之前操作仍存在；mock 数据使用本地存储持久化，管理员演示页重置数据后才会恢复种子状态。
