## 工程检查与证据

- `pnpm check:docs`：检查 Git 暂存区中的相对文档链接必须指向受版本管理的文件，CI 检查实际提交。暂存区以外的个人草稿不会混入结论。
- `pnpm verify`：领域/API/小程序/PC 单元测试、类型、打包与发布工具回归。
- `pnpm test:core-lifecycle`：独立测试数据库上的核心业务矩阵，CI 使用专用 PostgreSQL，禁止指向生产库。
- 首次运行 `pnpm exec playwright install chromium`，之后 `pnpm test:ui`：使用锁定版本的浏览器，自动启动本地 mock 服务，覆盖试听补齐课次、课程回填、102 条课表、连续代订和退款刷新失败恢复。输出 `output/ui-acceptance/`；CI 的 `core-ui-evidence` 附件保留 14 天。长期验收需要从该次 CI 下载归档，过期不声称附件仍可下载。
- `pnpm release:miniapp:prepare` / `pnpm release:miniapp:upload`：在干净源码上构建远端包、做原生 WXSS 编译和摘要校验，上传独立快照。机器回执位于 `output/releases/<版本>-<提交>/miniapp-release.json`；发布登记须摘录版本、提交、包摘要、上传结果与现场验收状态。

本地验证记录：API 单元 965 项、小程序单元 634 项（随后新增 1 项列表错误恢复回归）、共享 19 项、HTTP E2E 47 项通过；隔离 PostgreSQL 培训组 22 项通过；三个核心 H5 流程、远端微信/PC/API 构建和小程序类型检查通过。API 常规单元运行跳过的数据库用例不计作通过，完整数据库矩阵以本次 CI 为准。

当前 50 个数据库迁移，本轮无 schema 变更。新课表查询保留旧数组接口，新增分页和单条接口；应先部署服务端，再交付新小程序。CI 的 mock 交互和数据库矩阵均不能替代真实微信手机操作。

## 当前业务规则

- 游客可浏览页面和场次预约情况；浏览时不主动弹登录提示，提交本人业务时才登录。
- 管理员/超级管理员直接退款，申请人与审批人可相同；前台按授权代订包括过时或已占用场次，订单仍归会员并留审计。
- 场地数量、营业时间、地址和价格按球馆配置。
- 课程适用人群支持成人、青少年、不限；管理员可一次设置并发布课包限制，立即或定时生效。不把未来生效的规则当作已经可用。
- 异地备份、外部通知暂缓；需额外身份验证的网络安全工作跳过。真实微信现场验收未完成前不宣称全流程已验收。
