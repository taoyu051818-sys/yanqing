# 球局详情与定向邀请

## 用户旅程

1. 在「活动 → 日常球局」选择「查看球局详情」。列表负责选择球局，报名、查看名单和邀请统一放在详情中。
2. 「邀请球友」分享当前球局；微信卡片使用已有的比赛配图，H5 复制本场邀请链接。
3. 好友未登录也能查看标题、时间、费用、实际场地安排和名额。未安排场地时明确提示，不编造地址。
4. 登录后仍回到原球局，展示已确认报名球友的昵称、头像和自己的报名状态。待付款占位不计入正式名单。
5. 报名只创建一次订单并进入这一笔订单；不自动扣款。支付、取消后回到详情重新获取名额和名单。
6. 满员时进入候补，展示本人的队列位置，晋级前不生成付款订单。名额释放后复用现有 FIFO 晋级机制。
7. 未付款球局订单可取消：先关闭进行中的微信预支付，再在同一串行化事务内取消订单、释放本人名额、处理候补及写入审计。不能释放整场球局占用的球场。

## 路由和接口

| 用途 | 地址 | 边界 |
| --- | --- | --- |
| 正式球局详情 | `/pages/game-detail/index?id=<gameId>` | 主包注册页面，允许未登录浏览 |
| 好友邀请 | `/pages/game-detail/index?id=<gameId>&from=share` | 仅导航，不授予身份或触发报名 |
| 旧链接兼容 | `/pages/community/index?tab=games&gameId=<gameId>` | 一次性转入新详情，返回列表不循环打开 |
| 公共介绍 | `GET /games/:id` | 限已发布/进行中/结束/取消状态；草稿与不存在均返回 404 |
| 登录后名单 | `GET /games/:id/participants` | JWT 保护，仅公开昵称、头像、是否本人；订单只查询本人 |
| 球局报名 | `POST /games/:id/register` | 复用原报名幂等与占位逻辑 |
| 未付款取消 | `POST /orders/:id/cancel` | 本人或获授权岗位；已付款必须走退款，不允许直接取消 |

不向其他球友或访客返回手机号、会员账户余额、他人订单、用户 ID、经营激励或内部取消参数。主理人的昵称和头像属于球局的公开介绍。

H5 同一路由更换 `id` 会刷新球局，避免显示上一场内容。详情与订单相互查看时优先回到已经打开的同一记录，避免导航栈不断增长。名单会在回到详情、下拉刷新时同步，不宣称实时推送。

- 前端全量单元测试：188 项通过；前后端类型/构建检查通过。
- 微信主包检查通过：无未引用的主包 JS，remote 包不含 mock；图片/音频全部小于 200,000 字节。继续复用现有分享卡图，无新增大图。
- H5 专项回归脚本：`scripts/h5-game-detail-acceptance.cjs`，18 个检查点通过。涵盖游客邀请、复制链接、登录回跳、报名、取消、重新报名支付、名单变化、旧链接、同路由切换、满员候补、长昵称、头像失败和无效链接；检查 320 / 375 / 414 像素及桌面固定手机画布。
- 原会员旅程 H5 脚本：31 个检查点通过。截图使用独立模拟浏览器，不触碰用户会话或生产数据。
