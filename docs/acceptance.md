## 关键场景

1. 会员查看 20 片场地并下单；支付后从 `HELD` 变为 `CONFIRMED`，扫码后为 `CHECKED_IN`。同一场地/时段并发下单只能成功一次。
2. 五账户分别充值/扣减，确认任一流水不会改变其他账户；充值请求只提交当前有效 `planId`，服务端决定本金/赠送额且赠送不超过本金；联盟商户端不存在会员余额支付入口。
3. 通用分享入口只携带服务端签发的不透明邀请码，不暴露用户 ID；冷/热启动后登录自动完成一次性绑定，再次改绑必须失败。有效首单观察期结束后，邀请人与新客分别按当前参数获得奖励，不产生上级奖励；重复支付和重复批处理不得重复入账。
4. 球局报名支付后签到，满员后新会员进入 FIFO 候补；退款释放席位时最早候补自动生成待支付订单；主理人结束球局时按实际签到人数计算奖励；退款观察期内不提前发放，财务批处理可幂等补发。
5. 赛事少于 24 人签到不能开赛；完成五轮前不能完赛；固定双打、容量 48 人、让分起始分和 21 分封顶正确。会员双打报名必须由搭档本人生成赛事专用、15 分钟、一次性授权码，队长预览确认姓名后报名；同一账号不能跨队重复。进行中纠错会重算排名并留审计，完赛后封账并拒绝任何比分纠正。
6. 赛事草稿必须经过显式发布才开放报名；重复发布不重复写审计，已开始/已完成/已取消赛事不能再次发布。
7. 课包支付只增加预收余额；教练提交消课建议后由管理员确认才确认收入。对任意金额验证场馆合同收入为 20%，场地费和场馆应付款为 0。
8. 同一联盟券第一次核销成功，第二次失败且生成高风险事件；商户只能核销自己的券；结算支持提交、商户确认、异议（必填原因）和财务结算。
9. 商品支付后库存原子扣减；库存不足支付失败；寄售商品在订单行冻结供应商/佣金版本 1 快照，履约生成销售应付，整单退款回补库存并追加精确负数应付反冲；自营商品不生成应付。
10. 会员产品、充值计划和价格规则创建新版本后默认停用，启用时拒绝同编码/同适用范围的有效期重叠；历史订单快照不变。普通参数生成新生效版本，培训 20% 和零场地费参数不能改成其他值。
11. 财务账号只可导出 `orders` 与 `finance` Excel；管理员/超级管理员再分别验收会员、培训、赛事、联盟、库存、审计及全量范围。确认所有成功导出均进入审计日志，财务账簿不包含参数快照、幂等键、命令摘要或原始规则快照。
12. 使用内部角色调用 `GET /work-items`，确认退款、待消课、待录比分、待结算、低库存和待履约事项按责任角色返回；会员调用时返回空列表。
13. 退款申请人与审批人不能是同一账号；球局取消、赛事取消和赛事逾期支付产生的强制退款不可驳回；`REFUND_PENDING` 期间签到、完赛、履约和消课全部冻结。
14. 真实微信退款在 `REFUND.SUCCESS` 通知前保持处理中，通知重放不重复冲正账户。充值余额已被消费时退款仍保持成功，系统只追回可用余额并生成 `RECHARGE_REFUND_BALANCE_SHORTFALL` 风险事件记录未追回金额。
15. 寄售结算按 `DRAFT → PENDING_CONFIRMATION → CONFIRMED → SETTLED` 流转，争议/退回/作废保留历史，制单人不能确认或付款自己的单据，付款引用必填且重试不重复。
16. 日结只被待退款/支付、开放班次、未复核现金差异、到期未履约订单和未闭合培训课次阻断；培训、联盟、寄售周期结算仅在财务待办预警，并可在源营业日锁定后继续周/月流转。
17. 试听按预约→到课/未到→测评→转正式课/流失流转；青少年监管规则由管理员制订、超级管理员发布，产品和订单保存当时规则快照。
18. 前台、教练、赛事、商户、财务之间按对象和数据范围交接；越权、重复请求和非法状态动作均返回 4xx 并留下审计/风险记录。

### 本地真实闭环复验记录（2026-09-01）

- 全新 PostgreSQL 从空库应用 29/29 个迁移，`migrate status` 最新，Schema diff 为空；已种子化验收库也升级到第 29 个迁移且无漂移。
- 真实 HTTP 顺序回放：新客 B 绑定邀请人 A → 创建首充订单 → mock 微信支付完成 → 重放同一支付幂等键 → 财务发放成熟奖励 → 重放发放批次。
- 结果：关系只写入一次；支付重放返回同一 Payment；只有一个 `FIRST_PAYMENT` 奖励事件；A、B 各记一条 50 羽球币流水；发放重放 `processed=0`；绑定、奖励排队和发放均有审计。
- 本轮补充真实 HTTP/数据库回放：充值只增加现金本金；同一场地时段并发下单仅一笔成功；库存为零拒绝建单；会员工作项返回空数组；前台会员目录和 360 接口仅返回脱敏/汇总字段；已履约场地订单全额退款恢复现金本金且预约仍保留 `COMPLETED` 履约证据。
- 赛事搭档本人生成专用授权码后，队长预览并建立真实双账号队伍；数据库只存 64 位 SHA-256 哈希，原码不落库，消费后重用返回 409，搭档不能加入第二队。完赛赛事纠分返回 409，原比分及审计保持不变。
- `VITE_DATA_MODE=remote` 独立构建通过，产物为 `compileType=miniprogram`、测试 AppID `wxa457599ec4c27ad1`，运行分支确认不调用 mock；示例 API 地址只用于验证打包变量，不计作公网连通。
- 以上是后端与本地 remote 联调证据；微信分享卡点击、正式登录、真实支付/退款和体验版真机仍按下文补验。

## 微信验收

当前本地开发/预览构建使用测试 AppID `wxa457599ec4c27ad1`，构建产物应满足 `project.config.json.compileType = "miniprogram"`。在微信开发者工具导入 `apps/miniapp/dist/dev/mp-weixin`（开发）或 `apps/miniapp/dist/build/mp-weixin`（压缩构建/预览），不要导入源码目录。该测试号只用于编译和预览，不支持上传；本文不声称最终代码已经上传或已经通过真机。体验版需更换为支持上传且已授权的 AppID 后重新构建。先在 `VITE_DATA_MODE=mock` 下完成页面和角色旅程，再在 `VITE_DATA_MODE=remote` 下验证 API 持久化、权限和幂等。

在开发者工具和至少一台已加入体验成员的真机上逐项验证：微信登录、request 合法域名、扫码、支付/退款回调联调、弱网重试、分享返回、前后台切换、拒绝权限、安全区适配和不同屏幕尺寸。`urlCheck=false`、模拟支付、开发登录和本地 mock 只能作为开发演示，不能计为生产通过；真机不能访问电脑的 `127.0.0.1`，需使用 HTTPS 测试域名或受控局域网代理。生产 AppID、商户号、Secret、证书和 HTTPS 域名属于部署方资产，需在上线环境完成最终验收。

每条旅程记录角色、设备、AppID/版本、数据模式、订单/流水/风险事件 ID、前后状态、截图/日志和缺陷编号；完整记录模板见 [docs/wechat-devtools.md](wechat-devtools.md)。
