## 已核实的现状

现有公开网页是小程序的 H5 构建，不是独立 PC 管理后台。经营功能在小程序工作台及经营分包，已有人员查询、角色授予、停用、业务参数、课程产品、券模板、价格、财务、审计等界面/API，可作为 PC 后台的业务基础。

线上旧 H5 已下线，详情见[下线记录](releases/2026-09-05-h5-retirement.md)。小程序接口、数据库和上传存储保留，未修改角色或进行业务写入。

已完成真实超级管理员初始化和独立 PC 认证。PC 通过小程序真实微信身份确认，一次性二维码绑定发起浏览器，普通会员或开发登录不能确认。

## 两端分工

| 入口 | 主要用户与操作 | 边界 |
| --- | --- | --- |
| 小程序会员端 | 浏览、订场、报名、支付、取消、查看权益和邀请 | 普通会员不展示经营菜单或测试角色列表 |
| 小程序员工工作台 | 前台核销、教练签到与反馈、主理人履约、岗位待办、轻量审批 | 仅展示本人已授权岗位；迁移期间保留现有管理能力，不能造成无人可管理 |
| 独立 PC 管理后台 | 场馆负责人、管理员、财务进行集中配置、批量处理、复核与追溯 | 按桌面表格/日历/筛选/详情设计，不再套用手机宽度 |

两端共用同一会员/员工身份、订单、账户、数据库、API、审计和服务端规则。PC 可以有独立认证会话与发布流程，但不能另建一套业务账，也不能让浏览器直连数据库。

## PC 导航：先处理工作，再配置规则

采用分层导航、清楚的当前位置、明确任务详情和就地表单；按岗位逐步展开可用能力，避免全部菜单和编辑框同时出现。

1. **我的工作**：本人待办、跨岗位交接、异常；详情 → 处理 → 结果，处理完成自动离开待办。
2. **人员与权限**：会员查找、员工岗位、所属商户/场馆范围、停用、体验资格及授权记录。正式授予权限与“体验某个角色”分开。
3. **业务配置**：场地与一小时时段价格、课程产品/班级、球局/赛事、会员产品、券模板及适用范围、商品基础资料。按业务分二级入口；列表 → 详情 → 新建/版本变更 → 发布结果。
4. **经营履约**：订单查询、报名名单、课表、场地占用、库存作业和异常处理；不复制另一套订单状态。
5. **财务与复核**：退款、现金差异、调账、消课冲正、结算与对账。申请和审批分离，金额变更有依据与审计。
6. **系统与审计**：可配置分成等业务参数、操作记录、风险、登录会话。历史订单保留成交快照，不随当前参数变化被重算；不能任意删除财务历史。

首页默认“今天需要我处理什么”，经营分析为二级查看入口，不让图表取代工作入口。

## 身份、登录和体验模式

### 首位管理员

由项目所有者提供一个已微信登录账号的用户编号，或明确的已绑定手机号。核实唯一账号及微信绑定后，在单独明确授权下完成一次性初始化，并记录操作者、对象、原因和时间。之后在后台按权限授予/撤销岗位；不通过修改前端缓存或选择公共种子账号取得权限。

### PC 登录（V1 已实现）

已采用“小程序扫码确认登录”：PC 生成短时一次性登录会话，小程序扫码显示登录目标与待授予权限，真实员工确认后，PC 才获得自己的受限会话。二维码不得直接包含可复用的登录令牌；会话须绑定发起浏览器、防重放、可过期/取消/撤销，服务端每次操作校验有效用户与权限。

该流程使用 HttpOnly/Secure/SameSite=Strict Cookie 与 CSRF 防护，二维码 2 分钟有效、会话最多 8 小时，支持电脑与小程序撤销；权限与账号状态每次请求均重新核实。隔离 PostgreSQL 的真实 HTTP 验证已覆盖扫码审批、浏览器绑定、防重放和业务读写。真实微信扫码仍需用新版小程序验收。

线上已关闭开发登录并使未标记来源的历史令牌失效。环境仍保留现有 staging 与微信支付配置。

### 体验用户不是超级员工

“体验资格”是独立授权：谁授予、允许体验哪些岗位、有效期、撤销时间。正式岗位权限独立保存；切换角色不能自动拥有所有岗位的业务操作权限。

- 在正式环境只提供明确标注的只读角色预览，限制敏感信息展示；不能借预览执行退款、付款、改账、改角色等操作。
- 需要完整操作体验时，进入隔离测试环境，使用演示数据和模拟支付，不写线上订单/资产/库存。
- 全程保持真实操作者身份，不冒充另一个真实会员；体验到期/撤销后旧页面提交同样被服务端拒绝。

## 建设顺序与验收

第一阶段：确认真实超级管理员 → 完成 PC 安全登录与退出/撤销 → 关闭公共开发入口及处理旧测试会话 → 统一待办、人员授权和审计。

当前完成：真实超级管理员、开发入口关闭、旧令牌失效、PC 扫码认证与退出/撤销、待办概览、人员授权与审计；还接入会员产品、充值方案、场地价格、培训产品和联盟券模板配置。待办详细处理、财务复核、完整排课和批量作业仍在小程序，后续逐条迁移。

第二阶段：迁移最常用的课程、券、场地价格和会员产品配置。用 PC 配置、小程序立即看到生效结果、历史订单不变来验收；确保停用、版本生效时间、发行上限和商户券订场限制一致。

第三阶段：经营队列、财务复核、批量操作和对账。逐条验收跨端闭环，再逐步精简小程序中的重型管理页面；不先删除仍在使用的入口。

V1 实际地址为 `https://api.yutechhn.cn/admin/`，复用现有 HTTPS 证书并与 API 同源。`admin.yutechhn.cn` 未配置；未来迁移域名需同步调整精确 Origin 和反向代理。

完成标准：普通用户不能登录管理后台；管理员真实登录可追溯；岗位撤销即时生效；体验会话不能动真实资金；PC 与小程序的数据和状态自动同步；非法直接请求仍被服务器拒绝。
