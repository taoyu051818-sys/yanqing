# 小程序用户旅程整理与验收记录

日期：2026-09-05。范围：普通用户侧入口、页面层级、状态指引与移动布局；不改动生产数据库，不部署线上，不在本轮新增 PC Admin。

## 一、整理后的用户心智

用户先找到要做的事，再看详情、预约或报名；创建订单后，付款、使用与售后都回到自己的记录。首页不再承担经营功能目录。

| 用户现在想做什么 | 入口与下一步 |
| --- | --- |
| 订一片场地 | 首页主按钮／底部“订场” → 日期与可用时段 → 登录（保留选择） → 确认预约 → 对应订单 |
| 找人打球 | 首页“参加球局” → 找活动／日常球局 → 展开某场详情 → 报名 |
| 找课程 | 首页“找课程” → 成人／青少年课程 → 课程与班级 → 报名订单 |
| 参加比赛 | 首页“报名比赛” → 找活动／金羽积分赛 → 某场赛事详情与报名 |
| 看自己的安排 | “我的” → 我的订单／我的课程／我的活动；首页和“我的”优先提示待付款或待使用订单 |
| 查钱与权益 | “我的” → 钱包与权益；充值余额、赠送余额分别列账，未使用的零余额奖励默认折叠 |
| 查看和领取券 | “我的” → 我的卡券；先看已有券，领券与券码按需展开 |
| 邀请使用小程序 | “我的” → 邀请好友 → 分享小程序或复制邀请码 |
| 邀请一起打球 | 进入具体球局，再使用该球局的邀请入口，不与小程序推广混用 |
| 修改资料或处理隐私 | “我的” → 资料与设置；保留主动选头像、昵称和注销申请流程 |
| 员工履约 | 只有具有经营身份的用户，在“我的”看到经营工作台入口 |

底部导航稳定为：首页、订场、活动、我的。菜单不随余额和推荐活动任意改名、挪位。

## 二、收起什么，保留什么

- 去掉首页的角色展示、硬编码经营数字、财务口径与同权重入口堆叠。
- 不在个人中心平铺五类账户。钱包内仍独立记录充值余额、赠送余额、羽毛球币、赛事积分、成长积分，绝不混算总余额。
- 非零余额、冻结金额或已加载的相关变动记录会保留对应权益展示；“查看全部权益”始终可达。
- 青少年学员建档在选择青少年课程或报名需要时出现；课程费用明细折叠，剩余课时与有效期优先展示。
- 球局和赛事先给摘要，点击详情后再显示报名、搭档和比赛信息；我的报名与找活动明确分开，历史订单仍可查询。
- 商户核销不再出现在普通用户卡券页，原经营端核销能力保留。
- 资料编辑、邀请、隐私处理从个人首页抽到各自页面，不复制一套旧表单留在首页。
- 开发身份切换折叠，且仍受原开发构建开关限制；本轮没有把“体验角色”做成生产授权能力。

## 三、本轮修复

- 登录记住受保护的目标，返回订场时保留原选择并重新核验可售状态；不再默认把员工登录送到经营页。
- 订单支持按状态筛选、精确定位与分页；创建订单后进入该笔记录。
- 订场待付款支持取消；保留原服务端取消与超时占场规则，前端不自行伪造释放。
- 临时网络或服务器故障不再直接销毁登录；401 等身份失效仍清理会话。
- 修复 H5 按钮装饰层对文字点击的拦截；取消禁止浏览器缩放的 viewport 配置。
- 模拟接口补齐订单状态筛选、分页；修复仅修改昵称后无法再次登录的模拟数据问题。

## 四、验收证据与边界

本地隔离 MOCK 浏览器验收通过 31 个截图检查点，覆盖：

- 游客查看场地 → 选择 → 登录 → 返回保留选择 → 创建订单。
- 未付款订单占用该时段 → 取消订单 → 再次查询时段恢复可订。
- 首页待付款提醒能进入对应订单。
- “我的活动”进入我的报名；首页赛事入口回到找活动，不沿用错误的“我的”筛选。
- 课程入口、我的课时、钱包零奖励折叠和全部权益展开、普通用户卡券、昵称修改、邀请页面。
- 375px 手机尺寸、320px 小屏、1280px 桌面固定移动画布、812×375 横屏；检查按钮、输入框、卡片横向溢出。

浏览器使用独立临时会话，拦截所有非本地 HTTP 请求；未登录生产账号、未创建真实订单、未发送真实邀请或付款。

回归：34 个单元测试文件、173 项测试通过；小程序类型检查、H5 构建、微信小程序构建通过。构建仍提示原有 Browserslist 数据陈旧，不影响本轮编译。

这不是微信真机、真实支付、经营端权限安全审计或全部业务闭环的完成证明。头像选择、微信分享与微信支付仍需真机验收；日常球局待付款的独立取消、培训退费等应按其现有业务接口继续专项验收。没有用隐藏按钮替代服务端权限。

PC Admin 的用户授权、体验身份、权限有效期和审计仍是单独阶段，本轮没有新增生产环境的角色切换后门。

## 五、复现

验收脚本：`scripts/h5-member-journey-acceptance.cjs`。

先显式构建本地模拟包并用静态服务启动，再执行：

```sh
VITE_DATA_MODE=mock VITE_ENABLE_REMOTE_DEV_LOGIN=false pnpm --dir apps/miniapp build:h5
# 用本地静态服务器将上述构建产物挂到 http://127.0.0.1:5184
JOURNEY_BASE_URL=http://127.0.0.1:5184 JOURNEY_OUTPUT=artifacts/member-journey node scripts/h5-member-journey-acceptance.cjs
pnpm typecheck:miniapp
pnpm --dir apps/miniapp exec vitest run --config vitest.config.ts --maxWorkers=2 --minWorkers=1
pnpm build:miniapp
```

脚本需要 Playwright 与本机 Chrome。当前截图与 `results.json` 保存于工作区外层 `outputs/h5-member-journey-2026-09-05`；独立模拟预览放在该目录的 `preview` 内，避免与后续正式构建混用。测试会选当天尚可售的时段，因此需在当天仍有可售时段时运行。
